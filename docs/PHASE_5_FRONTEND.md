## Build Order

### Step 28 — Sandbox Primary View (`/sandbox`)
- Configuration Editor: visual builder + raw JSON toggle
- Run Launcher: run type selector (Quick / Full Production / Scenario), pre-run cost estimator displayed before launch
- **Routing Mode Selector prominently displayed:** BUILD / VALIDATE (+ remaining budget) / PRODUCTION
- Active Run View: live metrics stream + agent trace stream via WebSocket
- Improvement Inbox: APPROVE / REJECT / MODIFY AND APPROVE on proposals

**Cost tracker always visible in Sandbox header.** Remaining Claude budget for current run + estimated total session spend. No surprises.

### Step 29 — Signal Card UI (BUY + CLOSE)
Both card types match the wireframes in §8.3 and §8.4 of blueprint exactly:
- Position spec: shares, dollar value, % of portfolio, expected hold, price target, stop
- Agent Reasoning section with anchored citations (hover to highlight source)
- Signal Anchors section showing each passing condition with value and threshold
- System Track Record section — **anchored to held-out window Sharpe, not optimization window**. Shows "N/A — promote to unlock" for pre-promotion configs.
- Model attribution line: `Supervisor: Claude Sonnet 4.6 (uncertainty: 0.79)` or `Supervisor: Qwen 2.5 8B (uncertainty: 0.31)`
- **Non-dismissible disclosure:** "This signal was generated by an AI system and is not financial advice."
- ACCEPT / DECLINE action buttons. ACCEPT mirrors paper trade. DECLINE records counterfactual.

### Step 30 — Mirror Portfolio Dashboard (`/sentinels > Mirror Portfolio`)
- Paper portfolio NAV vs. real account NAV (user-entered real figures)
- Counterfactual breakdown by decision type (declined BUY, declined CLOSE)
- Gap analysis: exact dollar and percentage point gap attribution
- "Your best judgment call" / "Your worst judgment call" callouts

### Step 31 — MLflow Arena (`/arena`)
All seven views from §7.3:
1. Leaderboard — sortable by any metric, one-click config diff
2. Config Diff Viewer — git-style parameter diff + performance delta
3. System Evolution View — config lineage in chronological order
4. Parallel Coordinate Plot — parameter regions vs. Sharpe
5. Scenario Survival Matrix — scenario types vs. configurations
6. LLM vs. Quant-Only View — Phase 1 vs. Phase 2 Sharpe comparison
7. Cost Attribution View — Claude vs. Qwen win rates, spend per run, router calibration status
8. Proposal Decision Log — all proposals, outcomes, time-to-decision
9. Promotion Flow — held-out reveal + side-by-side + promotion confirm

### Step 32 — Engine Library (`/engines`)
- `/engines/data` — connector catalog, health status (MONITORING/DEGRADED/OFFLINE always visible)
- `/engines/fundamental` — engine params, current signal state
- `/engines/analyst` — agent configs, model routing config, trace history
- `/engines/research` — ChromaDB status, filing coverage
- `/engines/plugins` — all OFF by default, activation flow with tier check
- `/engines/custom` — SDK registration UI, registered engines, validation status

**Connector health is always visible** — never buried in settings. OFFLINE state suspended Signal Card generation must be immediately apparent.

### Step 33 — Glass Box Audit View
- Complete signal audit trail: data snapshot → Fundamental Engine → Custom Engines → signal gate → Research/Sentiment/Risk agents → Supervisor
- All factual claims in reasoning are linked to their source (hover to highlight)
- Custom engine sections collapsible, with `describe()` output as tooltip
- MLflow Run ID shown with direct link
- Monospace font throughout

### Step 34 — New Sentinel Wizard (`/create`) — 6-step, thesis-first
1. **What do you believe?** — thesis articulation. No template shown yet.
2. **Template matching** — recommended templates based on articulation. User selects or starts from scratch.
3. **Asset universe and capital** — tickers, benchmark, declared paper portfolio capital
4. **Data sources and signal gate** — connector selection, gate condition config
5. **Position sizing and exit conditions** — sizing method, stop, target, max hold, Proving Ground criteria
6. **Routing mode and validation budget** → launch into Sandbox

If custom engine with `RISK_OVERRIDE` role added: explicit confirmation required at Step 5.

### Step 35 — Dashboard (`/dashboard`)
- All active Sentinels: name, version, health state (MONITORING/DEGRADED/OFFLINE), live paper P&L
- Pending Signal Cards (BUY queue + CLOSE queue sorted by uncertainty score)
- Mirror Portfolio summary per Sentinel
- Monthly Claude spend tracker (current vs. estimated remaining)
- Recent agent activity (last 5 signal events across all Sentinels)
